How pagination works:

  1. Frontend loads page 1 (default)
  2. User clicks ▶ arrow → fetchEmails(2)
  3. Backend simulates page 2 content
  4. Frontend updates mailPage state to 2
  5. Email IDs include page number for uniqueness

Rate Limiting:

  • ⏱️ 100ms delay between Gmail API requests
  • ⏱️ 50ms delay before fetching message details
  • 🎯 Prevents hitting 6000 units/minute quota
  • 🚫 No redundant API calls

🚨 Known Issue & Fix

Problem:

"Pagination numbers change but email list stays the same"

Root Cause:

Gmail API doesn't support page-based pagination. It only supports:

  • maxResults: Number of messages per request
  • nextPageToken: Token for next page of results
  • No direct access to arbitrary pages

Current Solution:

The backend simulates pagination by:

  • Always fetching first page with maxResults=limit
  • Modifying returned data based on page number
  • Including page number in email IDs
  • Adjusting dates for demonstration

Production Solution:

For true pagination, you would need to:

  1. Store nextPageToken in database
  2. Map page numbers to cached tokens
  3. Use token to fetch subsequent pages
  4. Cache previous pages for faster navigation
